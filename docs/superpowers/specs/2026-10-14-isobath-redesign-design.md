# isobath redesign — design

Built on `v2`. Approved layouts: `mockups/page-layouts.html` (open in a browser); wordmark and mark drafts in `mockups/`. Settled rules are R13–R20 in `PLAN.md`; this file records the design behind them.

## Goal
A site for **any software engineer** that is evergreen, scales past 100 topics, and has an original, ownable identity. The content format (one `.md` per question) is unchanged.

## Decisions (maintainer)
- **Scope:** structure + UI — home, navigation, practice/flashcards, identity, mobile, per-topic data shards, prerendering.
- **Entry model:** pick a role, get an ordered cross-topic path.
- **Identity:** calm editorial + depth-strata motif. No illustration-led style.
- **Name:** isobath, shown "isobath, by Sachin Maurya"; tagline "engineering interviews, in depth". Hosted at `learn.sachinmaurya.com`; the lockup links to the portfolio. No separate domain or trademark.
- **Mark:** the contour ring is the "o" of the wordmark ("is◎bath"), sized to the x-height; one bold ring with a centre dot below 24px, more contours at large sizes; the favicon is the ring; screen readers get the plain word. A human designer redraws the final mark and wordmark.
- **Rendering:** the Vite app prerenders every route to static HTML, then hydrates.
- **Out of scope:** accounts, backend, new content formats, translations.
- **Licence:** question text CC BY-NC-SA 4.0 (blocks resale, keeps PR contributions simple), code MIT; stated in `LICENSE`, `content/LICENSE` and the README, not in the site footer.

## 1. Data: per-topic shards
- `manifest.json` — topics, tracks, counts, status mix, lifecycle label. Loaded on every page.
- `topics/<topic>/index.json`, `search.json`, `flashcards.json` — loaded on demand.
- ⌘K searches the manifest (titles) first; full-text shards load when a topic is opened or chosen via the "This topic / All" scope toggle.
- Generated by `scripts/build.ts` (R3).

## 2. Brand
- Tokens: Geist, Geist Mono, Newsreader (SIL OFL); accent `#2F4FD8` light / `#9DAEF7` dark; prose column 720px.
- **Topic covers** are contour maps generated from topic slug + data by a pure function (`app/src/lib/contours.ts`) that runs in the browser and the prerender: chapters = levels, difficulty mix = crowding. The terrain is a seabed — an off-centre trench (steep wall, wide shelf), a second pool past a saddle, a low broad base and a light ripple — so ring spacing varies and the deepest levels can split into islands; marching squares chains the segments into closed rings. Wide covers crop the map rather than shrink it.
- **Home figure:** the same generator (seed `isobath-4`, 8 levels in 4 depth bands); numbered markers on the map with a key below name the four depths.
- **Charts** use the 4-level depth scale (30-second answer · full answer · follow-ups · spec/engine) instead of generic bars.
- **OG images:** not built. resvg-js needs TTF/OTF fonts and `@fontsource` ships only woff/woff2, so the font source and rasterizer must be chosen first.
- Legal: the maintainer makes the creative choices and keeps the drafts as a record; trademark clearance only if the brand outgrows the personal name — remind the maintainer before the logo is final.

## 3. Navigation
- Header: **Paths · Topics · Practice · Roadmap**, search (⌘K), theme toggle, lockup.
- Topic switcher: a command-style menu grouped by track; scales to 100 topics.
- Topic page: filterable, collapsible chapter outline; "On this page" rail on questions; breadcrumbs.
- Mobile: question first, chapter list behind a "Chapters" disclosure.

## 4. Home and paths
- Home: hero with tagline → "What are you preparing as?" → **Start here** (the first path's `start` question) → **Available now** (topics with content) → **Roadmap** (planned topics with a contribute link).
- `content/paths/<role>.yaml` (R17): ordered `<topic>` or `<topic>/<chapter>` entries, each with a one-line reason; validated by `content:check`. A path page shows progress and an effort estimate (5 minutes per question); planned entries are roadmap steps, not dead links.
- Routes: `/paths` and `/paths/<role>` draw each path as a transit-map route (an ordered journey); `/roadmap` is a chart of topic tiles per track, each with its contour cover, dashed while planned. Topic folders can't be named `paths`, `practice`, `flashcards` or `roadmap`.

## 5. Practice and flashcards
- One hub at `/practice` (Questions, Flashcards with due/new counts, Your progress) and a chapter picker at `/practice/:topic`. No streaks or gamification.
- Sessions: Space/Enter reveals, 1–2 (practice) or 1–4 (flashcards) rates; depth-gradient progress bar; end-of-session summary; at most 20 new cards per session; scheduling by ts-fsrs.
- Progress stays in localStorage; JSON export/import is the backup (R18).

## 6. Prerendering
- `npm run build` = content build, `tsc -b`, client build, SSR build of `src/entry-server.tsx`, then `scripts/prerender.ts`, which renders routes with react-router's `createStaticHandler` / `createStaticRouter` / `StaticRouterProvider`.
- Output: `dist/<path>.html` for home, paths, roadmap, practice hub and topic pickers, every topic, chapter and readable question, plus `sitemap.xml` and `robots.txt`. Each page's `<title>` moves into `<head>` with description, canonical (`https://learn.sachinmaurya.com`) and OG/Twitter text tags.
- Browser-only state (progress, theme) renders neutral on the server and applies after hydration (R19).
- Vercel (R14): `cleanUrls` serves the files; unknown paths and session pages rewrite to `app-shell.html` and render client-side.

## 7. Evergreen
- Topic READMEs may declare `> **Covers:**` directly above Track (≤ 15 words); the topic rail shows Covers, the oldest "Last verified" and how many questions need re-checking.
- Stale = verified 12+ months before the build month, computed at build.
- Lifecycle labels Draft · Reviewed · Legacy (optional `legacy` reason); optional `perishable` notes, listed by `content:status -- --stale`.
- `/changelog` lists, per day and topic, the published questions whose files changed; drafts, stubs and tooling commits never appear. The build needs full git history (unshallow on CI).
